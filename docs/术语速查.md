## 1. 景别（Shot size）

**裁定：中文提示词按中文影视教材的五/七级景别写；需要英文时用下表右列，避开有歧义的 long shot。**

| 中文 | 画面范围（中文教材） | 推荐英文 | 说明 |
|------|----------------------|----------|------|
| 大远景 / 超远景 | 人物极小或成点，交代地理与规模 | extreme wide shot（EWS） | SB-景别：EWS/ELS，主体在环境中很小 |
| 远景 | 环境为主，人物很小 | wide shot（WS） | SB-景别把 long shot 与 wide shot 视为同义；但 Veo 把 “full shot or long shot” 解释为头到脚（人物全身）。为避免模型误解，**远景写 wide shot，不写 long shot** |
| 全景 | 人物全身 + 周边环境 | full shot（FS） | SB-景别：full shot＝头到脚。**中文「全景」不是 panorama（全景照片/360°）** |
| 中景 | 膝盖以上 | medium wide shot（MWS） | 中文教材：中景＝膝盖以上；SB-景别的 medium wide 为膝盖以上，cowboy shot 为大腿中部以上 |
| 中近景 | 腰部以上 | medium shot（MS） | SB-景别：medium shot＝腰部以上 |
| 近景 | 胸部以上 | medium close-up（MCU） | SB-景别：MCU＝胸部以上 |
| 特写 | 肩部以上（脸）或单个物体 | close-up（CU） | SB-景别：CU 以脸为主 |
| 大特写 | 更小的局部（眼睛、手指、刀尖） | extreme close-up（ECU） | SB-景别：ECU＝局部细节 |

模型文档的景别词表：SD1.0 列出远景、全景、中景、近景、特写 5 级；SD2.5 列出大全景、全景、中景、近景、特写。两者与上表中文用词一致，写中文提示词可直接用。

**库内用法差异：**
- `运镜/43`（胡小绿）原片字幕用「超远景 / 远景 / 全景 / 中景 / 微距特写」，并按信息量选景别（「镜头 6 全景→远景」），与上表一致。
- `运镜/43` 策展者写的英文对照表原把「中景」写成 Medium Shot「约腰部以上」，与中文教材不符，2026-09-30 已改为 MWS／膝盖以上（该表不是原文，可以改）。
- 部分分镜网站把「近景＝close-up、特写＝extreme close-up」，比中文教材整体小一级。本库以中文教材为准：近景≈MCU，特写≈CU。
- `长镜头` 在中文里指**长时间不剪的镜头（long take / 一镜到底）**，不是 long shot（远景）。依据：SB-长镜头。
- **库内用法差异：** `打斗运镜/34`（爆老师）字幕「中景贴身 · 保留全身动作」——按本节定义，保留全身已是全景（full shot）的范围，不是膝盖以上的中景；写提示词时想要全身动作就写全景。该片用甩镜换向，而甩镜也常用来藏剪辑点（见第 8 节「甩镜转场 / 隐形剪辑」），所以「一次没切」无法只凭成片证明。

## 2. 运镜（Camera movement）

**裁定：写清「摄影机本身移动」还是「只改焦距 / 只转机头」，一个镜头写一种主运镜。**

| 中文 | 英文 | 定义（出处） | 易混点 |
|------|------|--------------|--------|
| 固定镜头 | static / locked-off shot | 摄影机不动（SB-运镜；SD1.0 有 `camera_fixed` 参数） | — |
| 摇（摇摄） | pan（水平）/ tilt（俯仰） | 机位不动，机头水平转或上下转（SB-运镜；Veo） | ≠ 横移 |
| 推 / 拉（摄影机移动） | dolly in / dolly out（push in / pull out） | 摄影机**实际向前或向后移动**（SB-运镜；Veo） | ≠ 变焦 |
| 变焦推 / 变焦拉 | zoom in / zoom out | 机位不动，**改变焦距**放大缩小（SB-运镜；Veo） | 透视不变，和 dolly 观感不同 |
| 移（横移） | truck left / right | 摄影机侧向平移（SB-运镜） | ≠ pan |
| 升 / 降 | pedestal up / down（或 crane up / down） | 摄影机垂直升降（SB-运镜） | ≠ tilt（俯仰只转机头） |
| 跟 | tracking / follow shot | 摄影机跟随主体移动（SB-运镜；SD1.0「跟随」） | — |
| 环绕 | arc / orbit | 摄影机绕主体弧线移动（SB-运镜；Luma camera_motion 词表有 “orbit left/right”） | — |
| 摇臂 / 吊臂 | crane / jib | 摄影机随臂沿弧线升降摆动（SB-运镜） | Adrian：摇臂沿弧线摆动，升降是垂直换高度 |
| 航拍 | aerial / drone shot | 无人机或直升机拍摄（SB-运镜；Veo） | FPV 是高速穿越式航拍 |
| 手持 | handheld | 手持拍摄的自然晃动（SB-运镜；Veo） | 不是随机剧烈抖动 |
| 甩镜 | whip pan | 极快的摇，画面拉出运动模糊，常用作转场（SB-运镜；SB-转场） | — |
| 移焦 / 焦点转移 | rack focus | 焦点在前后景之间转移（SB-运镜；Veo） | 不移动摄影机 |
| 希区柯克变焦 | dolly zoom（vertigo effect） | 推/拉与反向变焦同时进行，主体大小不变、背景透视变化（SB-运镜；SD2.5 列出「希区柯克变焦」） | 主体大小必须保持 |

**中文「推镜头」的歧义：** 中文教材里的「推」既可以是摄影机前移，也可以是变焦推近；SD1.0 把推、拉、摇、移、环绕、跟随、升、降、变焦分开列。**写提示词时明确写「摄影机向前推近（dolly in）」或「变焦推近（zoom in）」**，不要只写「推」。

**库内用法差异：**
- `运镜/42`、`运镜/41`（AdrianPunk115）对「摇摄 vs 横移」「俯仰 vs 升降」「变焦 vs 推拉」「希区柯克变焦 vs 普通变焦」的区分与上表一致。
- `运镜/41`（Adrian）原文建议组合运镜时「短镜头最多安排两个主动作」（例如跟拍加一次环绕），并写清触发点；SD2.0 官方则建议「一个镜头里尽量只指定 1 种运镜方式」。**裁定：用 Seedance 2.0 时一个镜头只写一种运镜；确实需要组合时，按 Adrian 的「主运镜 + 次运镜 + 触发点」写且不超过两个，或者按官方建议拆成两个镜头。** 两者方向一致（都反对堆砌运镜），只是上限不同。

## 3. 角度（Camera angle）

| 中文 | 英文 | 说明（出处：SB-角度；Veo） |
|------|------|----------------------------|
| 平视 | eye level | 与人物视线齐平 |
| 仰拍 / 低机位 | low angle | 从下往上拍，显得人物高大有压迫感 |
| 俯拍 / 高机位 | high angle | 从上往下拍，显得人物渺小 |
| 顶拍 / 鸟瞰 | overhead / bird's-eye view | 垂直向下 |
| 荷兰角 / 斜角 | Dutch angle（Dutch tilt） | 画面倾斜，制造不安（StudioBinder https://www.studiobinder.com/camera-shots/camera-angles/dutch-angle-shot/ ） |
| 过肩 | over-the-shoulder（OTS） | 从一人肩后拍另一人 |
| 主观镜头 | POV | 角色的眼睛看出去（Veo 支持 POV） |

**库内用法差异：** `运镜/41`（Adrian）区分「镜头翻滚（摄影机在转）」与「荷兰角（已经斜了）」，与上表一致；「POV 里不应出现完整主角」也与 POV 定义一致。

## 4. 速度：快慢镜、升格 / 降格、变速

| 中文 | 英文 | 定义 |
|------|------|------|
| 升格 | overcranking | 拍摄帧率高于播放帧率，播放时成为**慢动作**（SB-升格；SB-帧率） |
| 降格 | undercranking | 拍摄帧率低于播放帧率，播放时成为**快动作**（SB-帧率） |
| 慢动作 / 慢镜头 | slow motion | 画面动作比真实时间慢（SB-慢动作） |
| 快动作 | fast motion / time-lapse（延时为极端情况） | 画面动作比真实时间快（SB-帧率） |
| 变速 / 速度坡度 | speed ramp | 同一镜头内从常速平滑过渡到慢速或快速（No Film School https://nofilmschool.com/2018/07/essential-tips-will-help-you-master-speed-ramping-premiere-pro ；SB-帧率）。SD2.5 官方用词为「回弹变速」 |
| 子弹时间 | bullet time | 时间近乎静止、摄影机绕主体移动（SD2.5 列出「子弹时间」） |

**裁定：** 「升格」只表示慢动作，不表示「画面升级」；「降格」只表示快动作。对 AI 模型，直接写「慢动作（升格）」「快动作（降格）」「由常速骤然变慢再恢复（变速）」比只写行业黑话更稳。

**库内用法差异：** `国风古装/20` 原文「升格慢动作」「空中争夺（升格）」用法与定义一致。`运镜/41`（Adrian）指出「长镜头管剪辑、慢动作管时间速度」，与 SB-长镜头 / SB-慢动作一致。

## 5. 节奏与卡点

| 中文 | 英文 | 说明 |
|------|------|------|
| 卡点 | cut / hit on the beat | 剪辑点或动作落在音乐节拍上（行业通俗用法；无统一权威定义，本表按库内用法描述） |
| 分镜 / 镜头序号 | shot list（Shot 1 / 镜头1） | SD2.0：用「镜头1 / 镜头2」分段；Kling 3.0：`Shot N (Xs)` |
| 时间戳 | timestamp（0–3s） | **模型相关**：SD2.0 官方称「模型对精确时间（如 0–3 秒）的支持不稳定」，应用镜头序号；SD2.5 官方称「响应整数秒的时间戳」，且时间戳应连续、不要用时间戳规定频率 |

**裁定：** 给 Seedance 2.0 写「镜头1、镜头2…」；给 Seedance 2.5 可用连续的整数秒时间戳；给 Kling 3.0 用 `Shot N (Xs)`。库内大量条目使用 `0–3s` 式时间码（标签「时间码分段」），用于 Seedance 2.0 时效果可能不稳定，这是模型差异，不是原文错误。

## 6. 奔跑与动作感

- SD2.0 官方建议：优先写**缓慢、连续的小幅动作**，避免狂奔、大跳、剧烈翻滚等高强度动作；情绪要外化为可见的身体细节（官方给了对照表）。
- SD2.5 官方建议：动作以概括描述为主，只细写需要被记住的关键动作。
- **与库内作者的冲突：** 孔明（`打斗运镜/32`）与胡小绿（`打斗运镜/33`）的武戏提示词写的是高强度招式和发力链。**裁定：** 需要高强度动作时，按 SD2.0 官方建议的「武戏分段拼接」——每段只写 1–2 个招式、单一运镜，再拼接；不要在一个镜头里堆满连续招式。

## 7. 打击感（Impact）

「打击感」不是影视教材的标准术语，是动作片和游戏圈的通俗说法。库内唯一系统定义来自孔明（`打斗运镜/32` 图 4，作者原文）：

- 发力链条：蹬地 → 转胯 → 送肩 → 发力 → 出刀
- 受力反馈：气浪 / 震动 / 飞溅 / 目标反应
- 画面张力：刀光轨迹 / 空间压迫 / 环境互动
- 镜头语言：机位 / 运动 / 节奏 / 近景特写

**裁定：** 以作者原文为准，本表不另下定义。与官方文档的关系：SD2.0 要求「动作细节」写因果与身体细节，与「写发力链、写受力反馈」方向一致；但强度要按第 6 节分段处理。

## 8. 转场（Transition）

| 中文 | 英文 | 定义（SB-转场，另见 StudioBinder 跳切 https://www.studiobinder.com/blog/what-is-a-jump-cut/ 、硬切对比 https://www.studiobinder.com/blog/what-is-a-smash-cut-definition/ ） |
|------|------|------|
| 硬切 | cut / hard cut | 直接切换 |
| 猛切 / 冲击切 | smash cut | 突然切到反差极大的画面 |
| 跳切 | jump cut | 同一机位时间跳跃造成的跳动 |
| 匹配剪辑 | match cut（graphic match / match on action） | 形状或动作相似的两个画面相接 |
| 声音先入 / 后出 | J-cut / L-cut | 声音早于或晚于画面切换 |
| 甩镜转场 / 隐形剪辑 | whip-pan transition / invisible cut | 用甩镜或遮挡掩盖剪辑点 |
| 淡入淡出 / 叠化 | fade / dissolve | 渐隐渐显或两画面叠化 |

模型支持：Veo 文档列出 match cut、jump cut、montage 等剪辑术语；SD1.0 用「镜头切换」表示多镜头。

## 9. 光影质感（Lighting）

| 中文 | 英文 | 说明（出处） |
|------|------|--------------|
| 三点布光 | three-point lighting（key / fill / back） | 主光、辅光、轮廓光（SB-布光） |

## 10. 各模型对否定词的支持（写约束时查这里）

| 模型 | 官方说法 | 建议写法 |
|------|----------|----------|
| Runway Gen-4 | 「Negative phrasing is not supported and may produce unpredictable or even opposite results」（Runway Gen-4） | 只写想要的，用正面描述代替「不要」 |
| Google Veo | 负面提示用名词列出不想要的元素，不要写 “no / don't”（Veo） | 放在单独的 negative prompt 字段 |
| Seedance 2.0 | 可以写「不要生成 Logo / 水印 / 字幕」等约束（SD2.0） | 约束放在末尾，短而具体 |
| Seedance 2.5 | 否定式控制只建议用于字幕与音频（SD2.5） | 其他问题改用正面描述 |

**注意（SD2.0 符号约定）：** （）表示音乐、<> 表示音效、{} 表示台词、【】表示字幕。库内很多模板用【】作占位符，**用于 Seedance 时要先替换成实际内容**，否则可能被当成字幕渲染。
