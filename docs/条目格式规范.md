# 条目格式规范

> 本文由策展者编写。适用于 `prompts/` 下所有 Markdown 文件。`scripts/build_index.py` 按本规范解析，格式不符时脚本会报错。

## 1. 文件骨架

每个文件按以下顺序组织，标题层级固定：

1. `# 分类 · 来源名`：一级标题，只出现一次。
2. `## 来源概述（非原文）`：来源链接、来源类型、作者 / 发布方、许可、收录日期、历史质检记录、本文件条目数与核对状态。
3. 条目。
   - **列表型文件**（一条来源一个条目，如 HF 精选、网页汇编）：`## N. 中文标题（原标题）`，下面依次是元数据块、`text` 围栏、可选的「策展备注（非原文）」引用块。
   - **长文型文件**（抖音图文 / 视频、X 长文、多来源方法论汇编）：保留原文的章节结构，只在每个 `text` 围栏前插入元数据块；原文标题的文字不改，层级可以调整以统一全库（例如 X 长文正文标题统一从 `####` 开始）。
4. `## 总结（非原文）`：放在文件末尾。长文型文件把原来开头的「策展者总结」移到这里，后面附「本文件统计」。

文件里其他不是原文的内容都要标「非原文」或「策展备注」。

## 2. 元数据块

选型：用 `yaml` 代码块而不是表格。理由：① 每个字段一行，人读起来清楚，GitHub 上也有代码块高亮；② 每个值都用 JSON 编码（字符串带双引号、标签是数组），既是合法 YAML，也可以逐行用 JSON 解析，AI 和脚本都不会歧义；③ 表格放不下长的核对说明，也难以区分空值。

```yaml
# 条目元数据（策展者添加，非原文）
id: "fight-camera--32-douyin-kongming-weapon-fight--01"
标题: "枪刺"
原标题: ""
分类: "打斗运镜"
标签: ["打斗", "古风"]
适用模型: "未指定（原文为通用中文 AI 视频提示词）"
语言: "zh"
来源链接: "https://www.douyin.com/note/7662990755169914127"
镜像: "短链 https://v.douyin.com/wCMSOojlXnU/"
作者: "孔明AI剧社（抖音）"
发布日期: "2026-07-16"
热度: "抖音 点赞 4,140 · 收藏 5,374 · 评论 47 · 分享 768（2026-09-30 抓取）"
许可: "author-shared-on-douyin; copyright-retained (孔明AI剧社); learning-archive"
原文类型: "image-transcript（图文配图逐字目视誊写）"
核对状态: "verified"
核对说明: "2026-09-30 对照原图 01–05.jpeg 逐字复核一致"
完整性: "完整"
备注: ""
```

规则：

- 第一行必须是注释 `# 条目元数据（策展者添加，非原文）`，字段顺序固定为上例的 18 个字段，缺的值写空字符串 `""`，不能省略字段。
- 元数据块和 `text` 围栏之间只能有空行。
- 每个 `text` 围栏前都必须有元数据块；不计数的代码块（作者的方法说明、词表、结构骨架）用**不带语言标记**的代码块，不加元数据。

### 字段说明

| 字段 | 含义与取值 |
|------|------------|
| id | `分类英文代号--文件名（不含 .md）--文件内序号（两位）`，全库唯一。文件改名或条目增删时会变化，引用时以「文件 + 标题」为准 |
| 标题 | 中文标题。来源是英文标题时由策展者翻译，原文标题放「原标题」；HF 条目用数据集提供的中文标题 |
| 原标题 | 来源的原始标题（与「标题」相同时留空） |
| 分类 | 所在的中文分类目录 |
| 标签 | 按规则自动识别的写法特征（如「时间码分段」「分镜/多镜头」「一镜到底」「参考图/素材引用」「负面约束」「慢动作/变速」「打斗」）+ 来源自带的标签。规则见 `scripts` 生成过程，标签只作检索参考 |
| 适用模型 | 优先用作者帖文或来源页的明确标注；其次是来源标题中的模型；都没有时写「未指定」。括号里说明依据（如「来源标注」「HF 数据集标注」「正文提及」） |
| 语言 | `zh` / `en` / `ja` / `zh+en`（中文为主夹英文） / `en+zh` |
| 来源链接 | 最权威的出处：作者原帖 > 官方页面 > 发布该提示词的网页或仓库 |
| 镜像 | 实际抓取所用的镜像或数据集（如 HF 数据集编号、twiscan、短链） |
| 作者 | X 条目写 `@账号（显示名）`；网页写发布方并注明「发布方」；无法确认时写「未知」 |
| 发布日期 | Asia/Shanghai 日期。X 条目取帖子时间；帖子不可访问时由帖子 ID 推算并注明 |
| 热度 | 抓取时的公开互动数，注明平台、抓取日期；来源没有公开互动数时写「未知（来源无公开互动数据）」。**不估算、不编造** |
| 许可 | 来源声明的许可或本库的归档标签；来源未声明时写「未注明（来源未声明许可）」 |
| 原文类型 | `文本`；`文本（X 长文 Article 代码块）`；`image-transcript（…）`：图片或视频画面文字的目视誊写；`ASR`：语音转写 |
| 核对状态 | `verified`：与原始出处逐字一致；`verified-with-fix`：发现转录错误，已按原始出处更正；`source-unreachable`：原始出处本轮无法访问，只能与镜像核对；`source-contradicts`：与更权威的出处有出入，未改动，列为待决 |
| 核对说明 | 核对依据、差异说明（如「原帖末尾多一个句号，未改动」） |
| 完整性 | `完整`；`完整（含 N 处【?】…）`；`片段：…`（来源本身就是片段，例如画面止于「……」） |
| 备注 | 其他策展说明（如 HF 规格、说明文字未收入围栏的原因） |

## 3. `text` 围栏（原文）

- 内容是来源中的**完整原文**，逐字、逐标点保留，包括原文的换行、错别字、【?】标记和画面上的「……」。
- 不润色、不翻译、不补全、不合并。唯一允许的改动是**证明为转录错误的更正**：必须在元数据「核对说明」写明依据，并在 `docs/CURATION-LOG.md` 和整合清单中列出前后对照。
- 帖子里的说明文字、话题标签、日文版、作者评论等不属于提示词的内容不放进围栏，在「备注」或「核对说明」里说明。

## 4. 非原文文字的写法

- 用简体中文、全角中文标点；英文术语、模型名、代码、链接保持原样，中英文之间留一个空格。
- 数字与单位：`15 秒`、`9:16`、`2026-09-30`。
- 引用库内文件用反引号路径，例如 `运镜/42-x-adrianpunk115-camera-dictionary-part1.md`。
- 时间一律写 Asia/Shanghai（UTC+8）。

## 5. 索引

- `INDEX.md`（人读）与 `index.jsonl`（机读）由 `scripts/build_index.py` 生成，同时更新 `prompts/README.md` 中两个 `<!-- 统计 -->` 标记之间的统计表。
- `index.jsonl` 每行一个 JSON 对象：上述 18 个字段 + `条目类型`（`prompt` 或 `case`）+ `文件` + `锚点`（GitHub 标题锚点）+ `所在标题` + `原文`。`cases/` 下的样例也各占一行（`条目类型`: `case`）。
- 修改后运行 `python3 scripts/build_index.py`；提交前运行 `python3 scripts/build_index.py --check` 确认同步。
