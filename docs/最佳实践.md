# AI 视频提示词最佳实践（综合官方指南与本库原文）

> 本文由策展者编写，**非原文**。每条结论都注明出处：官方文档优先，其次是本库收录的作者原文（给出库内路径），社区经验单独标注「社区说法」。术语口径见 `docs/术语速查.md`。2026-09-30 编写。
>
> 出处简称与链接同 `docs/术语速查.md`「常用出处」：SD2.0 / SD2.5 / SD1.0（火山引擎 Seedance 官方指南）、Veo（Google Cloud）、Runway Gen-4、Kling 3.0、Luma、StudioBinder。

## 1. 先定目标模型，再定写法

不同模型对同一种写法的反应不同，下面几条是**模型相关**的，写之前先确认用哪个模型：

| 问题 | Seedance 2.0 | Seedance 2.5 | Kling 3.0 | Veo | Runway Gen-4 |
|------|--------------|--------------|-----------|-----|--------------|
| 分段方式 | 「镜头1 / 镜头2」；精确时间（如 0–3 秒）支持不稳定（SD2.0） | 支持整数秒时间戳，时间轴要连续（SD2.5） | `Shot N (Xs)`，多镜头最长 15 秒（Kling 3.0） | 用自然语言分句描述（Veo） | 一个 5–10 秒片段只写一个场景（Runway Gen-4） |
| 否定写法 | 可写「不要生成 Logo / 水印 / 字幕」（SD2.0） | 否定只建议用于字幕和音频（SD2.5） | — | 单独的负面提示，只列名词，不写 no / don't（Veo） | 不支持，可能适得其反（Runway Gen-4） |
| 结构 | 主体 + 动作细节 + 场景环境 + 光影色调 + 镜头运镜 + 视觉风格 + 画质 + 约束条件（SD2.0） | 素材指代 → 一句话概述 → 具体情节 → 结尾（SD2.5） | 每个 Shot 写景别、动作、台词（Kling 3.0） | 主体、动作、场景、镜头角度与运动、镜头与风格、时间、音频（Veo） | 先写简单提示，再逐步增加细节；只描述运动，不重复描述图片内容（Runway Gen-4） |

## 2. 通用写法（多数官方指南一致）

1. **写具体的主体和动作，不写空泛形容词。** SD2.0 公式以「精准主体 + 动作细节」开头；Veo 的提示结构同样以主体、动作开头。本库孔明（`打斗运镜/32` 图 4 原文）的「错误示例」也是同一道理：「动作很帅、刀光很亮」效果差，要写发力链条和受力反馈。
2. **一个镜头只写一种主运镜。** SD2.0：「一个镜头里尽量只指定 1 种运镜方式，不要同时要求推拉摇移」。Adrian（`运镜/41` 原文）：组合运镜时短镜头最多两个主动作，并写清触发点。裁定见术语速查第 2 节。
3. **运镜写起点、方向、终点和保持项。** Adrian（`运镜/42` 原文）第七节「只写方向，没有起点和终点」列为常见问题；Veo 与 Luma 都用明确的运动短语（如 “camera orbit left”）描述摄影机运动。
4. **区分「摄影机移动」和「变焦」。** 写「摄影机向前推近（dolly in）」或「变焦推近（zoom in）」，不要只写「推」。依据：StudioBinder 运镜指南、SD1.0 把「推、拉」与「变焦」分列。
5. **情绪写成看得见的身体细节。** SD2.0 给出了「情绪具象外化」对照表（如紧张 / 焦虑写成「频繁地看手表、手指不停敲击桌面、呼吸急促」），替代「很悲伤」「非常愤怒」这类抽象词；本库 `提示词写法/01` 第 3 节收录了翔宇整理的情绪外化对照（原文）。
6. **光影写光源、方向和质感。** SD2.0 把「光影色调」列为独立一段；Veo 列出具体光线词（Rembrandt、high-key / low-key、volumetric、backlight / silhouette、golden hour）。
7. **音频单独成句。** Veo 建议把音频描述写成单独的句子；SD2.0 约定（）表示音乐、<> 表示音效、{} 表示台词、【】表示字幕。
8. **用参考素材时先声明映射关系。** SD2.0 示例：「将视频1中的高个子男人定义为警察……」；SD2.5 要求多主体时逐一列清映射关系。SD2.0 建议素材控制在 4–5 个以内。
9. **先简单后复杂，迭代加细节。** Runway Gen-4 明确建议从简单提示开始，确认基础运动后再加细节。

## 3. 动作戏与打斗

1. **高强度武戏分段生成再拼接。** SD2.0：追逐、打斗、蒙太奇等复杂快速的「武戏」适合「分段拼接」（独立生成片段再剪辑组合），剧情连续的「文戏」适合「视频延长」。
2. **单段内优先写小幅、连续的动作。** SD2.0：「优先选用缓慢、轻柔、连贯的细微动作，尽量规避狂奔、大跳、剧烈翻滚等高爆发、大动态动作」。
3. **写发力链和受力反馈（打击感）。** 孔明（`打斗运镜/32` 原文）：蹬地 → 转胯 → 送肩 → 发力 → 出刀；受力反馈写气浪、震动、飞溅、目标反应。
4. **按信息量选景别。** 胡小绿（`运镜/43`、`打斗运镜/33` 原文）：攻防动作用中景看清身体距离；技能影响整个战场用全景或超远景；近景和特写会「看不清双方怎么打」。
5. **想要临场感时，试试一条不剪的长镜头。** 爆老师（`打斗运镜/34` 画面字卡原文）：「十秒 · 零剪辑点」「手持跟拍全程不落定」「出招即换向」；长镜头不闷「靠三件事：镜头不停 / 环境挨打 / 人数压迫」。注意：原视频用甩镜换向，甩镜常被用作转场，所以「一次没切」无法从成片证明；完整提示词作者没有公开（见 `打斗运镜/34` Blockers 一节）。

**冲突与裁定：** 官方建议低强度动作，而本库的武戏作者写的是高强度招式。两者不矛盾——**强度来自拼接后的整体节奏，单段仍保持 1–2 个招式、单一运镜**。SD2.5 也建议动作以概括描述为主，只细写需要被记住的关键动作。`打斗运镜/34` 的一镜到底也不和「分段拼接」冲突：它是单段 10 秒内的一条连续镜头，靠镜头运动和环境反应制造燃感，而不是在一段里堆高爆发招式。

## 4. 时长、字数与分段

1. **Seedance 2.0 用镜头序号，Seedance 2.5 可用秒级时间戳。** 依据：SD2.0「模型对精确时间（如 0–3 秒）的支持不稳定」；SD2.5「Seedance 2.0 不响应时间戳只响应镜头序号，而 Seedance 2.5 响应整数秒的时间戳」。库内大量 `0–3s` 式条目（标签「时间码分段」）若用于 Seedance 2.0，可能不按时间执行。
2. **时间戳要连续，不要用时间戳规定频率。** SD2.5 明确要求时间轴连续，避免「0-3 秒……5-6 秒……」这类跳跃写法。
3. **字数（社区说法，未见官方数字）：** 翔宇工作流称「单镜头 60–100 词；多镜头序列 200–300 词；低于 30 词模型会随机脑补，超过 300 词后半段容易被忽略」（https://xiangyugongzuoliu.com/seedance-video-prompt-guide/ ）。这是社区经验，官方指南没有给出词数上限，使用时当作参考而不是规则。

## 5. 约束与否定

1. **按模型选择否定方式。** 见第 1 节表格：Runway 只写正面；Veo 用独立的名词式负面提示；Seedance 2.0 可写「不要生成 Logo / 水印 / 字幕」；Seedance 2.5 否定只建议用于字幕和音频。
2. **能用正面描述的，优先正面描述。** Runway Gen-4 和 SD2.5 都倾向正面描述；翔宇整理的「正面约束模板」（`提示词写法/01` 第 3 节原文）也是同一方向。
3. **替换模板占位符。** 库内很多模板用【】作占位符。SD2.0 约定【】表示字幕，直接粘贴可能生成字幕，使用前要替换成实际内容。

## 6. 结构模板（社区说法，已移出计数的旧条目）

2026-09-30 整合时，下列三条策展者转述（不是原文）从 `提示词写法/01` 的计数围栏中移除，要点保留在这里并标明出处：

- **四段式结构（Seedance 2.5）：** 素材指代 → 一句话概述 → 具体情节（时间戳或「镜头 N」）→ 结尾收束。社区文章 SunoMV https://suno.bi/zh/blog/seedance-2-5-prompt-guide 这样总结；与 SD2.5 官方结构一致，**以官方为准**。
- **色调三层：** 主色调（大面积基底）/ 次色调（主体相关的中间层）/ 点缀色（一两个反复出现的小面积高光）。出处同上（SunoMV，社区说法）。
- **长度指引：** 见第 4 节第 3 条（翔宇工作流，社区说法）。

## 7. 本库使用建议

- 找可直接用的提示词：看 `INDEX.md`（按分类）或 `index.jsonl`（每行一条，含完整原文和元数据）。
- 想先学写法：`提示词写法/`（方法论原文）→ `运镜/42`、`运镜/41`（运镜词典）→ `运镜/43`、`打斗运镜/33`（景别选择）→ `打斗运镜/32`（打击感）→ `打斗运镜/34`（一镜到底）。
- 想让特效和画面融合：`特效/40`（核心光效 / 动态轨迹 / 环境联动三层）→ `特效/41`（力场扰动：写空气、布料、光影怎么被特效带动）。
- 没有具体目标、想找新思路：先翻 `INDEX.md` 最上方的「技巧锦囊」（想不到要问的技巧，每条附技巧钩子和触发场景）。
- 用前检查每条元数据里的「适用模型」和「核对状态」；`source-unreachable` 表示本轮无法回到原始出处重新核对。
- 模板里的【】、`<<<image_N>>>`、`@图1` 等占位符按目标模型的素材引用语法替换。

## 8. 已知冲突与裁定汇总

| 冲突 | 各方说法 | 裁定 |
|------|----------|------|
| 时间戳 vs 镜头序号 | SD2.0：时间不稳定，用镜头序号；SD2.5：支持整数秒；社区模板多用 `0–3s` | 按模型选：2.0 用镜头序号，2.5 可用连续时间戳，Kling 3.0 用 `Shot N (Xs)` |
| 否定词 | Runway：不支持；Veo：名词列表；Seedance：部分支持 | 按模型选，见第 5 节 |
| 动作强度 | SD2.0：低强度小幅动作；武戏作者：高强度招式 | 分段拼接，单段 1–2 招 |
| 一镜到底 vs 分段拼接 | 爆老师（`打斗运镜/34`）：10 秒零剪辑点更燃；SD2.0：武戏适合分段拼接 | 不冲突：一镜到底是单段内的连续镜头，靠运镜和环境反应撑燃感；跨段仍分段拼接 |
| 「力场」管不管光影 | AI琪琪（`特效/41`）：「Field 力场扰动模拟」让全域光影跟着特效联动；Blender / Houdini 文档：力场只改变运动，光照和折射由灯光与渲染完成 | 原文不改。写提示词时把运动（风压、气流）、光影（随特效变色）、折射（热浪扭曲）分开写清楚；「Field」一词本身未见模型专门响应的证据（见 `特效/41` §3） |
| 每镜运镜数 | SD2.0：1 种；Adrian：组合时最多 2 个主动作 | Seedance 单镜 1 种；组合需写触发点，或拆镜 |
| 中景范围 | 中文教材：膝盖以上；部分英文对照写成腰部以上 | 中景＝膝盖以上（MWS），腰部以上是中近景（MS） |
| long shot | StudioBinder：＝wide shot；Veo：＝full shot | 不写 long shot；远景写 wide shot，全景写 full shot |
| 宿舍短剧示例措辞 | lanshu kit 版本与火山引擎官方示例 1 有 3 处字词差异 | 未改原文，列入 MANIFEST 待决事项 |
