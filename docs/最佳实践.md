## 1. 先定目标模型，再定写法

不同模型对同一种写法的反应不同，下面几条是**模型相关**的，写之前先确认用哪个模型：

| 问题 | Seedance 2.0 | Seedance 2.5 | Kling 3.0 | Veo | Runway Gen-4 |
|------|--------------|--------------|-----------|-----|--------------|
| 分段方式 | 「镜头1 / 镜头2」；精确时间（如 0–3 秒）支持不稳定（SD2.0） | 支持整数秒时间戳，时间轴要连续（SD2.5） | `Shot N (Xs)`，多镜头最长 15 秒（Kling 3.0） | 用自然语言分句描述（Veo） | 一个 5–10 秒片段只写一个场景（Runway Gen-4） |
| 否定写法 | 可写「不要生成 Logo / 水印 / 字幕」（SD2.0） | 否定只建议用于字幕和音频（SD2.5） | — | 单独的负面提示，只列名词，不写 no / don't（Veo） | 不支持，可能适得其反（Runway Gen-4） |
| 结构 | 主体 + 动作细节 + 场景环境 + 光影色调 + 镜头运镜 + 视觉风格 + 画质 + 约束条件（SD2.0） | 素材指代 → 一句话概述 → 具体情节 → 结尾（SD2.5） | 每个 Shot 写景别、动作、台词（Kling 3.0） | 主体、动作、场景、镜头角度与运动、镜头与风格、时间、音频（Veo） | 先写简单提示，再逐步增加细节；只描述运动，不重复描述图片内容（Runway Gen-4） |

## 2. 通用写法（多数官方指南一致）

1. **写具体的主体和动作，不写空泛形容词。** SD2.0 公式以「精准主体 + 动作细节」开头；Veo 的提示结构同样以主体、动作开头。本库孔明（`打斗运镜/32` 图 4 原文）的「错误示例」也是同一道理：「动作很帅、刀光很亮」效果差，要写发力链条和受力反馈。
2. **一个镜头只写一种主运镜。** SD2.0：「一个镜头里尽量只指定 1 种运镜方式，不要同时要求推拉摇移」。Adrian（`运镜/41` 原文）：组合运镜时短镜头最多两个主动作，并写清触发点。裁定见术语速查第 2 节。
3. **运镜写起点、方向、终点和保持项。** Adrian（`运镜/42` 原文）第七节「只写方向，没有起点和终点」列为常见问题；Veo 与 Luma 都用明确的运动短语（如 “camera orbit left”）描述摄影机运动。
4. **区分「摄影机移动」和「变焦」。** 写「摄影机向前推近（dolly in）」或「变焦推近（zoom in）」，不要只写「推」。依据：StudioBinder 运镜指南、SD1.0 把「推、拉」与「变焦」分列。
5. **情绪写成看得见的身体细节。** SD2.0 给出了「情绪具象外化」对照表（如紧张 / 焦虑写成「频繁地看手表、手指不停敲击桌面、呼吸急促」），替代「很悲伤」「非常愤怒」这类抽象词；本库 `提示词写法/01` 第 3 节收录了翔宇整理的情绪外化对照（原文）。
6. **光影写光源、方向和质感。** SD2.0 把「光影色调」列为独立一段；Veo 列出具体光线词（Rembrandt、high-key / low-key、volumetric、backlight / silhouette、golden hour）。
7. **音频单独成句。** Veo 建议把音频描述写成单独的句子；SD2.0 约定（）表示音乐、<> 表示音效、{} 表示台词、【】表示字幕。
8. **用参考素材时先声明映射关系。** SD2.0 示例：「将视频1中的高个子男人定义为警察……」；SD2.5 要求多主体时逐一列清映射关系。SD2.0 建议素材控制在 4–5 个以内。
9. **先简单后复杂，迭代加细节。** Runway Gen-4 明确建议从简单提示开始，确认基础运动后再加细节。
10. **参考一职一角，并写明不要转移什么（社区说法）。** Emily2040 skill 的 reference transfer contract：每个 `@Image/@Video/@Audio`（或官方写法「图片1/视频1」）只领一个主职（身份 / 首帧 / 运镜 / 动作 / 音色等），并用 ignore 子句挡住串味。官方仍以「映射声明」为准；句式与短摘录见 `技巧锦囊/45` §3。来源：`Emily2040/seedance-2.0` `references/reference-transfer-contract.md`。
11. **叙事抽象词落成可见载体（社区说法）。** 欲望、权力、潜台词不要原样进生成提示词；改成机位、视线、道具动作、站位前后差。见 `技巧锦囊/45` §2（Emily `directors-read.md`）。与官方「写具体主体和动作」一致，不替代官方公式。
12. **单镜先定保真度主花销（社区说法）。** 身份稳定 / 运动强度 / 场景密度三者抢同一预算，每镜一个 primary。见 `技巧锦囊/45` §4（Emily `allocation-model.md`）。多镜时每块末尾重申光、身份、站位与机位侧（lock line，同节）。
13. **空间写到可度量，首帧即占位（社区说法）。** Hell Grind CINEDANCE：用 within 1 meter / hand on … 等替代 near/around；开场第一帧就要读清人物与地标关系，避免空建立镜。显式写 **camera side**（机位在主体/光源哪一侧）。薄摘录见 `技巧锦囊/46` §2–3。不替代官方主体/动作公式。
14. **表演写压力下行为；动作写状态不写过程链（社区说法）。** Hell Grind ACTING：objective 下的可见行为，而非情绪标签；常驻角色 master profile 约 150–220 词，每场改写进当下（勿整段粘贴）；**eye life**（saccades / catchlights / eyes-lead-thought）强制；动作用 mid-throw 等已在状态，少写 reach→pull→wind-up 过程链。见 `技巧锦囊/46` §4。与官方「情绪具象外化」（§2.5）同向，不替代发力链（`打斗运镜/32`）。

## 3. 动作戏与打斗

1. **高强度武戏分段生成再拼接。** SD2.0：追逐、打斗、蒙太奇等复杂快速的「武戏」适合「分段拼接」（独立生成片段再剪辑组合），剧情连续的「文戏」适合「视频延长」。
2. **单段内优先写小幅、连续的动作。** SD2.0：「优先选用缓慢、轻柔、连贯的细微动作，尽量规避狂奔、大跳、剧烈翻滚等高爆发、大动态动作」。
3. **写发力链和受力反馈（打击感）。** 孔明（`打斗运镜/32` 原文）：蹬地 → 转胯 → 送肩 → 发力 → 出刀；受力反馈写气浪、震动、飞溅、目标反应。
4. **按信息量选景别。** 胡小绿（`运镜/43`、`打斗运镜/33` 原文）：攻防动作用中景看清身体距离；技能影响整个战场用全景或超远景；近景和特写会「看不清双方怎么打」。
5. **想要临场感时，试试一条不剪的长镜头。** 爆老师（`打斗运镜/34` 画面字卡原文）：「十秒 · 零剪辑点」「手持跟拍全程不落定」「出招即换向」；长镜头不闷「靠三件事：镜头不停 / 环境挨打 / 人数压迫」。注意：原视频用甩镜换向，甩镜常被用作转场，所以「一次没切」无法从成片证明；完整提示词作者没有公开（见 `打斗运镜/34` Blockers 一节）。
6. **开场两秒先交代对手、兵器、能量（社区说法）。** beshuaxian `05-fight-scenes`：前两秒读清「谁打谁+距离 / 武器或流派 / 快慢与重量感」。发力链仍以孔明（`打斗运镜/32`）为准。Seedance 2.0 上勿依赖精确 `0–0.5s` 时间码，改用「镜头1」写同信息。薄摘录见 `技巧锦囊/45` §6；**不**收录其多风格完整提示词。
7. **碰撞分三档，并且让镜头跟着受力。** 投稿四则（`打斗运镜/37`）：轻碰撞写短抽帧、局部负片、轴向微甩；重碰撞写更长抽帧、中心负片、猛沉回弹；大招写定格、全屏负片闪白、鱼眼。同一套雾山五行水墨已见于 `cases/打斗运镜/lansenai-ink-skill-30s`（无兵器单人技能）；这四条是带兵器的完整分镜。原文里的 0.05 秒 / 0.1 秒 / 0.15 秒，Seedance 2.0 不一定执行（见第 4 节、第 8 节），2.0 上保留档位和镜头反应即可。
8. **不站桩时写出地形路线；换场可以交给一个物件。** 同文件：悬崖古刹一条把每一击写成庭院、回廊、飞檐、塌顶、铜钟上的位移；怒江一条用一枚银币把镜头从竹筏带过满月，再落入竹林。竹林对决则把机位埋在竹叶后，先静一下再爆冲破屏。

**冲突与裁定：** 官方建议低强度动作，而本库的武戏作者写的是高强度招式。两者不矛盾——**强度来自拼接后的整体节奏，单段仍保持 1–2 个招式、单一运镜**。SD2.5 也建议动作以概括描述为主，只细写需要被记住的关键动作。`打斗运镜/34` 的一镜到底也不和「分段拼接」冲突：它是单段 10 秒内的一条连续镜头，靠镜头运动和环境反应制造燃感，而不是在一段里堆高爆发招式。

## 4. 时长、字数与分段

1. **Seedance 2.0 用镜头序号，Seedance 2.5 可用秒级时间戳。** 依据：SD2.0「模型对精确时间（如 0–3 秒）的支持不稳定」；SD2.5「Seedance 2.0 不响应时间戳只响应镜头序号，而 Seedance 2.5 响应整数秒的时间戳」。库内大量 `0–3s` 式条目（标签「时间码分段」）若用于 Seedance 2.0，可能不按时间执行。
2. **时间戳要连续，不要用时间戳规定频率。** SD2.5 明确要求时间轴连续，避免「0-3 秒……5-6 秒……」这类跳跃写法。
3. **字数（社区说法，未见官方数字）：** 翔宇工作流称「单镜头 60–100 词；多镜头序列 200–300 词；低于 30 词模型会随机脑补，超过 300 词后半段容易被忽略」（https://xiangyugongzuoliu.com/seedance-video-prompt-guide/ ）。这是社区经验，官方指南没有给出词数上限，使用时当作参考而不是规则。

## 5. 约束与否定

1. **按模型选择否定方式。** 见第 1 节表格：Runway 只写正面；Veo 用独立的名词式负面提示；Seedance 2.0 可写「不要生成 Logo / 水印 / 字幕」；Seedance 2.5 否定只建议用于字幕和音频。生图的 Midjourney 用 `--no` 列单个名词，正文不写「不要……」（`docs/术语速查.md` 第 10 节；`人物卡/40` 的两段原文正文里写了一串「不要……」，原文不改，见该文件 §3.1）。
2. **能用正面描述的，优先正面描述。** Runway Gen-4 和 SD2.5 都倾向正面描述；翔宇整理的「正面约束模板」（`提示词写法/01` 第 3 节原文）也是同一方向。
3. **生图（做首帧 / 尾帧）也按模型选否定方式。** FLUX.2、Runway Gen-4 Image 不支持负面提示；Gemini 用正面语义描述；Imagen、SD3.5、万相文生图有单独的负面字段；Midjourney 用 `--no`（写法见第 1 条）；GPT Image 的官方示例直接在提示词里写「No watermarks」。详见 `docs/术语速查.md` 第 10 节。
4. **替换模板占位符。** 库内很多模板用【】作占位符。SD2.0 约定【】表示字幕，直接粘贴可能生成字幕，使用前要替换成实际内容。

- **四段式结构（Seedance 2.5）：** 素材指代 → 一句话概述 → 具体情节（时间戳或「镜头 N」）→ 结尾收束。社区文章 SunoMV https://suno.bi/zh/blog/seedance-2-5-prompt-guide 这样总结；与 SD2.5 官方结构一致，**以官方为准**。

## 7. 本库使用建议

- 找可直接用的提示词：看 `INDEX.md`（按分类）或 `index.jsonl`（每行一条，含完整原文和元数据）。
- 想先学写法：`提示词写法/`（方法论原文）→ `运镜/42`、`运镜/41`（运镜词典）→ `运镜/43`、`打斗运镜/33`（景别选择）→ `打斗运镜/32`（打击感）→ `打斗运镜/34`（一镜到底）→ `打斗运镜/37`（三级碰撞、地形零站桩、铜币转场、竹叶埋机位）。
- 想写打光：`光影打光/40`（时段 + 方位角度 + 在主体上形成什么 + 背景；伦勃朗光、丁达尔光柱、硬光 / 柔光的写法）→ 术语见 `docs/术语速查.md` 第 9 节。
- 想让特效和画面融合：`特效/40`（核心光效 / 动态轨迹 / 环境联动三层）→ `特效/41`（力场扰动：写空气、布料、光影怎么被特效带动）。
- 做首尾帧 / 图生视频：先读 `docs/首尾帧工作流.md`，再看 `prompts/首尾帧生图/`（官方示例）；角色设定图在 `人物卡/`，但给 Seedance 2.0 当视频参考时改用大头照 + 全身照（见第 9 节）。
- 没有具体目标、想找新思路：先翻 `INDEX.md` 最上方的「技巧锦囊」（想不到要问的技巧，每条附技巧钩子和触发场景）。
- 写 Seedance 且要用社区 agent-skill 结构时：只读 `技巧锦囊/45` 与本节对应 bullet，**不要**把 Emily/dexhunter/beshuaxian 整仓拷进 `prompts/`；官方冷门技巧仍以 `技巧锦囊/35` 为准。
- 写 Hell Grind / 电影向空间锁与表演层时：只读 `技巧锦囊/46` 与本节 §2.13–14；**不要**把 CINEDANCE/ACTING/LIRA 全文拷进 `prompts/`；完整 skill 若已装在 agent 侧，以安装副本为准。LIRA 4-D **仅 IMAGE**，视频仍走 `35`/`45`/官方。
- 用前检查每条元数据里的「适用模型」和「核对状态」；`source-unreachable` 表示本轮无法回到原始出处重新核对。
- 模板里的【】、`<<<image_N>>>`、`@图1` 等占位符按目标模型的素材引用语法替换。

## 8. 已知冲突与裁定汇总

| 冲突 | 各方说法 | 裁定 |
|------|----------|------|
| 时间戳 vs 镜头序号 | SD2.0：时间不稳定，用镜头序号；SD2.5：支持整数秒；社区模板多用 `0–3s` | 按模型选：2.0 用镜头序号，2.5 可用连续时间戳，Kling 3.0 用 `Shot N (Xs)` |
| 亚秒级抽帧（0.05 秒 / 0.1 秒 / 0.15 秒） | `打斗运镜/37` 原文把轻 / 重 / 大招绑在这些时长上；SD2.0：精确时间不稳定，只稳定响应镜头序号 | 原文不改。Seedance 2.0 保留三档和对应的镜头受力（微甩、下沉回弹、鱼眼），不依赖亚秒数字；2.5 可用整数秒时间戳 |
| 否定词 | Runway：不支持；Veo：名词列表；Seedance：部分支持；Midjourney：用 `--no`，官方把正文里的「don't / without」列为错误示例；Ksr桑（`人物卡/40` 原文）正文写「完全不要CG感、不要3D渲染……」并同时写 `--no` | 按模型选，见第 5 节；Midjourney 以官方为准，原文不改 |
| 动作强度 | SD2.0：低强度小幅动作；武戏作者：高强度招式 | 分段拼接，单段 1–2 招 |
| 一镜到底 vs 分段拼接 | 爆老师（`打斗运镜/34`）：10 秒零剪辑点更燃；SD2.0：武戏适合分段拼接 | 不冲突：一镜到底是单段内的连续镜头，靠运镜和环境反应撑燃感；跨段仍分段拼接 |
| 「力场」管不管光影 | AI琪琪（`特效/41`）：「Field 力场扰动模拟」让全域光影跟着特效联动；Blender / Houdini 文档：力场只改变运动，光照和折射由灯光与渲染完成 | 原文不改。写提示词时把运动（风压、气流）、光影（随特效变色）、折射（热浪扭曲）分开写清楚；「Field」一词本身未见模型专门响应的证据（见 `特效/41` §3） |

## 9. 生图与首尾帧（给图生视频准备画面）

完整流程、参数表与逐条出处见 `docs/首尾帧工作流.md`；这里只列最容易出错的几条。

1. **先定视频模型，再按它的画幅出图，首尾两张同一画幅。** 画幅不一致时，Seedance 会拉伸或裁剪尾帧（SD2.5；SD-API），Firefly、BFL 会裁切或补边。
2. **尾帧从首帧编辑出来，一次只改一个条件。** OpenAI：每次只改一处并重复要保留的内容；需要像素级不变的区域，把编辑结果合成回原图（OpenAI-Img）。BFL：首尾帧保持同一主体、场景或机位，差距越大越不可预测（BFL）。
3. **首帧要干净、要「静」。** Runway：输入图里的伪影会被放大；运动模糊、扬尘、动作中途的姿势等隐含运动会和提示词打架，先用图像编辑去掉（Runway-I2V）。参考图里的文字先去掉（SD2.0）。
4. **角色参考用多张单视图。** Seedance 2.0：大头照 + 全身照，不用多视图（SD2.0）；Runway References：中性光线、中性表情（Runway-Ref）。
5. **视频提示词只写运动和过渡。** Runway：「focus almost exclusively on motion」（Runway-I2V）；万相 3.0：提示词重点写动态、剧情、台词与运镜（Wan3）。
6. **严格按分镜走用关键帧，不用宫格。** SD2.5：宫格分镜不会严格对齐；需要严格对齐时拆成独立图片，第一句写「以图片x至图片x的顺序作为关键帧」。
7. **官方未说明的不当规则。** 例如「首帧给运动留空间」的具体构图规则，本轮抓取的官方文档都没有给出。
8. **生图优化流程可参考 LIRA 4-D 指针（社区说法，IMAGE-only）。** Deconstruct→Diagnose→Deliver 纪律见 `技巧锦囊/46` §5；**不**把其 Soul/NBP 产品矩阵当通用规则；角色参考与首尾帧仍以本节 1–6 条与 `docs/首尾帧工作流.md` 为准。
