# 首尾帧工作流：从生图到图生视频（官方文档汇编）

> 本文由策展者编写，**非原文**。每一条做法后面的方括号是出处简称，链接、页面日期和逐字摘录见 `docs/权威来源.md`（2026-09-30 抓取）。**没有官方出处的做法，本文不写成规则**；这类地方标为「官方未说明」。可以直接复制的官方示例提示词在 `prompts/首尾帧生图/`。
>
> 出处简称：SD2.5 / SD2.0 / SD1.0（火山引擎 Seedance 提示词指南）、SD-API（火山引擎「创建视频生成任务 API」）、Seedream（火山引擎 Seedream 4.0-5.0 提示词指南）、Seedream API（火山引擎「图片生成 API」）、OpenAI-Img（OpenAI Image prompting guide）、Gemini-Img（Google Nano Banana image generation）、Imagen（Google Imagen prompt guide）、Veo（Gemini API Veo 3.1）、Veo-Vertex（Google Cloud 首尾帧 / 参考图文档）、Veo-PG（Google Cloud Veo prompt guide）、MJ（Midjourney 帮助文档）、Kling（可灵 3.0 用户指南 / 2.6 图生视频 API）、Runway-I2V / Runway-Img / Runway-Ref（Runway 帮助中心）、BFL（Black Forest Labs FLUX 文档）、Wan3（阿里云万相 3.0 指南）、Luma、Pika、Firefly（Adobe）。

## 0. 总流程

1. 选定视频模型 → 2. 按该模型的画幅和分辨率出图 → 3. 准备角色 / 场景参考 → 4. 出首帧（干净、无文字、无伪影、不带多余的运动暗示）→ 5. 用编辑从首帧做出尾帧 → 6. （可选）多关键帧 / 分镜 → 7. 写视频提示词：只写运动和过渡 → 8. 用尾帧接下一段。

## 1. 先选视频模型，再定图片尺寸

- **首尾帧两张图的画幅必须一致。** SD2.5：尾帧与首帧画幅不一致时「尾帧会被拉伸」；SD-API：宽高比不一致时「以首帧图片为主，尾帧图片会自动裁剪适配」[SD2.5][SD-API]。
- **首帧决定输出画幅的模型：** Seedance 用 `first_frame/last_frame` 时锁定输出宽高比，`ratio` 必须为 `adaptive` [SD2.5]；万相 3.0 建议 `ratio=adaptive` 自动匹配输入图片 [Wan3]；Midjourney Edit Model 会自动匹配第一张图的宽高比 [MJ]。
- **会被裁切的情况：** Seedance 图生视频若选择的宽高比与图片不一致，方舟「居中裁剪」[SD-API]；Firefly 在关键帧与画幅不符时提供 Crop Image 手动裁切 [Firefly]；BFL：比例不匹配会迫使模型「crop or pad」[BFL]。**所以出图时就按目标比例出，不要指望模型替你裁。**
- **Sora 2 已于 2026-09-24 下线**；其指南里「图片须与目标视频分辨率一致」的要求只作历史参考 [OpenAI 视频指南]。
- 生图模型的尺寸设置：GPT Image 2.5 自定义尺寸每边 ≤3840 px、两边为 16 的倍数、长短边比 ≤3:1，常用 2048x1152（2K 横）/ 3840x2160（4K 横）[OpenAI-Img]；Gemini 用 `aspect_ratio` 参数，官方示例也在提示词末尾写「Aspect ratio 16:9.」[Gemini-Img]；Seedream 5.0 的 `size` 推荐「分辨率档位 + 在 prompt 里用自然语言写宽高比或用途」，也可直接写宽×高像素，两种方式不可混用；可选范围按模型不同 [Seedream API]。
- 各模型的具体限制见第 8 节表格。

## 2. 锁角色、锁场景：参考图怎么准备

- **人物参考 = 大头照 + 全身照。** SD2.0：额外准备「只包含角色头部的人脸特写图」，「无表情最佳」；提示词写「<主体1> 的面部特征参考图片1（大头照），妆造参考图片2（全身照）」[SD2.0]。Runway References 同样建议光线自然均匀、表情中性，作为「blank canvas」[Runway-Ref]。
- **三视图 / 多视图拼图要看模型：**
  - Seedance 2.0：「不建议使用人物多视图」，三视图 / 多视图易导致认错人和「双胞胎」[SD2.0]。
  - Seedance 2.5：1–5 个主体时单视图、多视图都可以；超过 5 个主体时单视图更稳，多视角要拆成多张单独的图 [SD2.5]。
  - Gemini：多角度应逐个角度迭代生成，并把前面生成的图一起输入 [Gemini-Img]。
  - 可灵 3.0：元素（Element）用 2–4 张参考图创建 [Kling]。
    - 多人同框出现「双胞胎」时，Seedance 2.0 官方给了一句固定约束（`prompts/技巧锦囊/35` 第 5 节）。
- **结论：** 给视频模型的角色参考，优先用多张**单视图**图片（每张一个角度），不要用一张拼好的三视图；Seedance 2.5 且主体少时可以例外。`人物卡/` 里的三视图模板适合做设定图，不直接当 Seedance 2.0 的视频参考。
- **参考图数量上限：** Veo 3.1 最多 3 张参考图 [Veo]；Runway References 最多 3 张 [Runway-Ref]；MJ Edit Model 最多 4 张 [MJ]；Gemini 3.1 Flash Image 最多保持 4 个角色的相似度 [Gemini-Img]；Seedance 2.5 视频参考图编辑 1–5 张效果较好，6–8 张稳定性下降 [SD2.5]；Seedance 2.0 参考人物超过 4 人时稳定性下降，官方建议先把人物分组、每组不超过 4 人生成图片，再用这些图生成视频 [SD2.0]（见 `prompts/技巧锦囊/35` 第 8 节）。
- **风格先统一再生视频。** SD2.0：「建议将参考图先变为目标风格再进行生视频」[SD2.0]。
- **图里已有别的人时：** Runway 建议先用黑块盖住原图里的脸再上传，避免新旧主体混淆 [Runway-Ref]。
- Midjourney 的 `--cref/--cw` 是 V6 / Niji 6 的旧功能，V7 用 Omni Reference，V8.X 用 Edit Model [MJ]。

## 3. 出首帧：写法

- **写看得见的内容：** 主体 + 行为 + 环境，再补风格、色彩、光影、构图 [Seedream]；材质、光线、颜色、媒介、取景 [OpenAI-Img]；「镜头类型 + 主体 + 场景 + 光线 + 机位 + 镜头」模板 [Gemini-Img]。
- **少用空泛的氛围词：** 电影感、低光、雨夜、霓虹这类场景，要写尺度、氛围和颜色，不能只靠情绪词 [OpenAI-Img]；Seedream 5.0 lite / 4.5 / 4.0「采用简洁精确的提示通常优于重复堆叠华丽复杂的词汇」[Seedream]；「Specific detail helps. Filler hurts.」[BFL]。
- **相机参数只是外观提示：** OpenAI 明确说镜头 / 相机参数是外观线索，不保证物理模拟 [OpenAI-Img]。
- **人物写清取景：** 例如「full body visible, feet included」[OpenAI-Img]；Runway：想稳定得到全身，就描述鞋子或裤子 [Runway-Ref]。
- **画质修饰词看模型：** Imagen 官方列出「4K, HDR, Studio Photo」等修饰词 [Imagen]；Seedream 5.0 lite / 4.5 / 4.0 建议简洁、不堆叠华丽词汇 [Seedream]。**按目标生图模型决定，不当成通用规则。**
- **不要文字、水印：** 视频模型会把参考图里的文字带进画面；SD2.0 建议先去掉参考图里不必要的文字再输入，并说明横屏生成出字幕的概率明显低于竖屏 [SD2.0]（见 `prompts/技巧锦囊/35` 第 7 节）；OpenAI 建议在编辑提示里写明排除文字、Logo、水印 [OpenAI-Img]。
- **「不要 X」怎么写看模型：**
  - 不支持负面提示：FLUX.2 [BFL]、Runway Gen-4 Image（「may result in the opposite」）[Runway-Img]。改写成正面描述，例如 BFL 把 "no text" 换成 "clean surfaces / unmarked / blank" [BFL]。
  - 建议写成正面语义：Gemini「semantic negative prompts」[Gemini-Img]。
  - 有单独的负面字段：Imagen、Veo（只列名词，不写 no / don't）[Imagen][Veo-PG]；万相文生图 `negative_prompt` [Wan3 文生图]；SD3.5 `negative_prompt`（AWS Bedrock 平台文档）。
  - Midjourney：用 `--no`，官方把「without any fruit」写法列为反例 [MJ]。
  - GPT Image：官方示例直接在提示词里写「No watermarks」「Do not add new elements or text」[OpenAI-Img]。

## 4. 首帧要「干净」「静」

- **无伪影：** Runway：输入图就是第一帧，模糊的手或脸这类伪影「may be intensified」，所以要高质量、无伪影 [Runway-I2V]。
- **去掉隐含运动：** 运动模糊、扬尘、动作中途的姿势、方向线都是隐含运动；与之相反的运动提示需要更多次尝试，官方建议先用图像编辑去掉这些线索 [Runway-I2V]（示例见 `首尾帧生图/05` 第 2 条）。注意 Runway Gen-4 Image 的关键词表把「natural motion blur」当作一种生图风格 [Runway-Img]——**生图时好看，做首帧时反而会干扰运动方向。**
- **给运动留空间的构图：** 官方文档**未说明**具体的构图规则（例如主体偏在画面哪一侧）。本文不下结论，见 MANIFEST「待决事项」。

## 5. 做尾帧：从首帧编辑，而不是重新生成

- **一次只改一个条件。** OpenAI：把上一步的输出作为输入，只提一个改动，并重复要保留的细节 [OpenAI-Img]；官方示例「Make it look like a winter evening with snowfall.」只改天气。BFL 单图编辑示例「Change it to Night」「The woman is now looking at the camera」[BFL]；Gemini 编辑模板写明改哪个元素，并加「Keep everything else in the image exactly the same」[Gemini-Img]；Seedream：写明改什么，并「保持动作不变」[Seedream]。
- **两个互补视角也可以：** Veo 3.1 官方示例用正面中景作首帧、背后 POV 作尾帧，视频提示词只写 180° 环绕（`prompts/技巧锦囊/37`）。
- **首尾帧要相关。** BFL：两帧保持同一主体、场景或机位，插值才有合理路径；差距越大，模型自由度和不可预测性越高 [BFL]。
- **需要完全不变的区域，用合成而不是靠提示词。** OpenAI：反复编辑仍可能改动想保留的细节；要像素级不变，就把通过的编辑结果合成回原图 [OpenAI-Img]。
- **首尾用同一张图：** 火山引擎 API 允许首尾帧相同 [SD-API]；Runway 建议用 Animate Frames、首尾放同一张图来减少镜头运动，也可在提示词里写「The camera must start and end on the exact same frame to create a perfect loop.」[Runway-I2V]；Midjourney `--loop` 用首帧作结束帧 [MJ]。适合循环镜头和「几乎不动」的镜头。
- **尾帧的画幅和首帧一致**（见第 1 节）。

## 6. 多个关键帧 / 分镜

- **严格按分镜走：用关键帧，不用宫格。** SD2.5：多宫格分镜「不会严格对齐」，需要严格按分镜生成时，把分镜拆成独立图片按顺序输入，提示词第一句写「以图片 x 至图片 x 的顺序作为关键帧」[SD2.5]。
- **宫格分镜的画法：** 推荐火柴人 / 线稿；不推荐过度锐化、杂乱的 AI 直出分镜图，不推荐在分镜图上写过多文字；宫格数最好在 15 个以下 [SD2.5]。
- **其他模型的关键帧能力：** FLUX 3 支持 3 张以上关键帧或带时间戳的关键帧（需显式 duration），各帧观感要一致 [BFL]；Pika 2.5 支持 2–5 个有序关键帧 [Pika]；Veo 3.1 只支持首帧 + 尾帧 [Veo]；可灵 2.6 API 不支持只给尾帧 [Kling]；Luma API 可只给 `frame1`（尾帧）[Luma]。
- **一次出一组分镜图：** Seedream 用「一系列 / 一套 / 组图」或具体张数触发组图，API 需 `sequential_image_generation=auto`（Seedream 5.0 pro / flash 不支持组图参数）[Seedream][Seedream API]。

## 7. 写视频提示词

- **只写运动和过渡，不重复描述画面。** Runway：图生视频提示词「focus almost exclusively on motion」[Runway-I2V]（Runway《Gen-4 Video Prompting Guide》的同类示例见 `prompts/技巧锦囊/38`）；万相 3.0：图像已确定主体、场景与风格，提示词重点写动态过程、剧情、台词与运镜 [Wan3]；Veo 首尾帧示例只写两帧之间的动作 [Veo-Vertex]。
- **需要写画面的例外：** 引入画面里没有的元素、与首帧差别很大的变化、变形细节、多个元素的互动 [Runway-I2V]。
- **首尾帧都给了，也写提示词：** Firefly：提示词可选，但描述两帧内容会让过渡更平滑 [Firefly]。
- **Runway 的推荐结构：** 「The camera [motion description] as the subject [action]. [Additional descriptions]」[Runway-I2V]。
- **不想被剪开：** 加「Continuous, seamless shot」，或延长时长 [Runway-I2V]。
- **想让镜头尽量不动：** 「The locked-off camera remains perfectly still.」等写法 [Runway-I2V]。
- **首尾帧模式与参考模式互斥：** Seedance 的首帧、首尾帧、全模态参考 3 种场景不可混用 [SD-API]；万相 3.0 首尾帧模式与全能参考模式互斥 [Wan3]。需要角色参考时，Seedance 可改用 reference_image 并在提示词里写「图片 3 为首帧，图片 5 为尾帧」，但输出不锁画幅、首尾只是「相近」[SD2.5]。
- **动作强度：** Midjourney High Motion 可能产生「unrealistic or glitchy movements」[MJ]；SD2.0 建议单段动作缓慢连贯（见 `docs/最佳实践.md` 第 3 节）。

## 8. 接长：用尾帧接下一段

- Runway：拖到视频最后一帧，Use current frame，作为下一段的输入图；剪辑时去掉重复的那一帧 [Runway-I2V]。
- 火山引擎 API 可设 `return_last_frame=true` 直接返回尾帧图（jpeg，尺寸与视频一致，无水印）[SD-API]。
- Seedance 视频延长拼接处跳变：前一段末尾删 6 帧、后一段开头删 1 帧；最好在转场切镜处结束 [SD2.0]。多次续写画质下降时，官方建议先转成白模再续写（`prompts/技巧锦囊/35` 第 3、4 节）。

## 10. 出图前后自检

1. 目标视频模型定了吗？图片比例和它的输出比例一致吗？（第 1 节）
2. 首帧和尾帧：同一画幅、同一角色、同一场景 / 机位吗？尾帧是不是从首帧编辑出来的？（第 5 节）
3. 画面里有没有文字、水印、UI？有没有模糊的手和脸？（第 3、4 节）
4. 画面里有没有和你要的运动方向相反的运动模糊、扬尘、半空姿势？（第 4 节）
5. 角色参考：大头照 + 全身照？有没有误用三视图拼图？（第 2 节）
6. 视频提示词是不是只写了运动和过渡？「不要 X」的写法符合目标模型吗？（第 3、7 节）
